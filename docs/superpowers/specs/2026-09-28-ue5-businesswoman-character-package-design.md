# UE5 女角色可游玩交付包设计

## 目标

在现有 LALAGAME 仓库中增加一个独立、可直接打开的 UE 5.8 示例工程。开发者可以运行测试地图操纵女角色，也可以通过 UE 的“迁移”功能把完整角色复制到未来的 UE5 主项目。

## 交付位置

`UE5/BusinesswomanCharacterDemo/`

该目录是独立 UE 工程，不改变当前 `BarPrototype` 团结引擎工程，也不改变现有 Unity 构建和测试流程。

## 目录结构

```text
UE5/BusinesswomanCharacterDemo/
├─ BusinesswomanCharacterDemo.uproject
├─ Config/
├─ Content/
│  ├─ orc_character/Women_Motified_Ultimate/
│  ├─ Characters/
│  ├─ Input/
│  └─ ThirdPerson/
├─ SourceAssets/
├─ 打开角色示例.cmd
└─ README_角色使用说明.md
```

## 包含内容

### 角色美术

- 最终女性角色骨骼网格体。
- 基础颜色、法线、粗糙度、金属度等贴图及对应材质。
- 已调整的角色比例和骨骼绑定。
- 原始 GLB 与可继续编辑的 Blender 工程；若 Blender 工程引用外部贴图，则一并携带贴图。

### 动画系统

- 待机、八方向步行和慢跑动画。
- 跳起、下落和落地动画。
- 移动混合空间。
- 动画蓝图及移动速度、空中状态等驱动变量。
- 已绕过与该 Tripo 骨架不兼容的 UE 人偶脚部 Control Rig，防止腿部拉伸。

### 可操纵角色

- 基于 `Character` 的玩家蓝图。
- 胶囊体碰撞和 `CharacterMovement`。
- 第三人称弹簧臂与摄像机。
- WASD、鼠标视角、跑步、跳跃以及手柄输入映射。
- 默认游戏模式、玩家出生点和测试地图。

## 依赖策略

交付工程携带角色实际引用的 UE 第三人称模板资产，确保换电脑后不依赖创建模板时产生的隐式内容。资产保持原有 UE 包路径，避免二进制 `.uasset` 内部引用失效。

未来接入主工程时，开发者应在内容浏览器中对角色交付目录执行“资产操作 → 迁移”，由 UE 自动复制依赖，不能用资源管理器拆散 `.uasset`。

## 仓库与体积

- 只提交 `Content`、`Config`、`.uproject`、说明和源模型。
- 排除 `Binaries`、`DerivedDataCache`、`Intermediate`、`Saved`、本机日志和临时诊断脚本。
- `.uasset` 和 `.umap` 作为二进制文件处理。
- 当前最大单文件约 20 MB，低于 GitHub 100 MB 单文件限制。
- 若未来模型或贴图超过 100 MB，再启用 Git LFS；本次交付不要求开发者额外安装 LFS。

## 开发者工作流

1. 安装 UE 5.8。
2. 双击 `打开角色示例.cmd`。
3. 打开默认测试地图并点击播放。
4. 使用 WASD、鼠标和跳跃键验证操控。
5. 在未来主项目中通过 UE“迁移”导入角色资产。

## 验收标准

- `.uproject` 可由指定 UE 5.8 编辑器打开。
- 默认地图、默认游戏模式和默认玩家类设置正确。
- 地图检查为 0 个错误。
- 动画蓝图编译成功，最终姿势输出不经过不兼容的脚部 Control Rig。
- 角色在待机、移动、转向、跑步、起跳、下落和落地时保持正常比例，不发生根骨骼缩放错误或腿部拉伸。
- 材质和贴图引用完整。
- 新工程不依赖原测试工程的绝对路径。
- 仓库不包含缓存、日志、构建产物或用户私有配置。

## 完整可游玩人物的组成

一个可游玩人物至少需要：可变形网格、UV、材质和贴图、骨骼、蒙皮权重、动画片段、动画状态与混合逻辑、碰撞体、移动组件、输入映射、摄像机、玩家控制蓝图、游戏模式、出生点和可测试关卡。实际项目还通常需要脚步声、交互接口、受击与死亡逻辑、LOD、性能预算、网络同步、保存数据及授权记录；这些属于后续游戏功能，不是本次角色示例工程的必需范围。
