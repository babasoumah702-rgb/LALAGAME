## 本轮已经确定的方向

- 游戏为 UE5 第一人称 3D；首夜场地是顶楼酒吧，上方露台可看流星雨。四位角色来这里放松，不强加事业任务。
- 玩家不必填写长篇身份；入场后能自由看、走、说、点饮品，开场滚来的球是可参与也可忽略的小互动。
- 酒吧工作人员到时间点组织五人弹球入杯，规则和奖惩在报名之前说明。投球、命中和胜负必须来自真实游戏状态。赢／输带来社交机会，不直接买到好感或约会。
- 首夜的明确目标是与愿意同行的人看流星雨；浪漫同行、朋友同行、独自上楼、提前结算都能成立。被拒后仍有结算与后续可能。
- Kiko 与万塞是散打学员／教练，不是恋人或前任。四人不在同一家公司；新版不沿用旧 Demo 的 ECHO 纠纷、四人旧恋情和塔罗牌局。

## 原型默认值／仍待试玩的提案

- 酒单共九款，六款含酒精、三款无酒精；玩家试玩初始 Cash 暂按 **18**，价格和醉意点数见酒单。角色口味和微醺差异是**创作提案**，可在试玩后调整。
- X 仍是占位名；X／一桐的职业细节和四人之间部分熟悉程度还可细化，不阻挡首夜原型。
- 后台关系可沿用六维概念；界面先用易读的态度阶段与近期原因，是否显示数值待试玩。
- 技术主工程、Agent 服务端及最终 API 连接方式尚待技术同学核对。旧 Demo 是“玩家可填模型接口、默认 DeepSeek”的旧实现，**不能假定本包已经接入它或新 UE5 工程**。

## 版本优先级：请按这一条解决文件间的措辞差异

本轮**只做预设酒单的点单、赠送、接受／拒绝与实际饮用**；玩家亲手自由组合原料、特调评分与调酒小游戏留到下一轮。早期场景稿中的“做特调”可以暂按“点选吧台已有特调”理解，不应据此开发自由配方系统。温泉、攀岩馆是后续场景候选，本包不承诺它们已可游玩。开放式“天道”、完整城市、杀人／警局分支不在首夜纵向样板范围内。

## 可交付的第一条可玩链路

玩家进门并自由选择接近对象 → 点一款预设饮品，Cash 真正变化；赠送时角色能接受或拒绝；只有实际喝下才改变醉意 → 工作人员组织五人弹球，玩家和四人可见地出手并得出真实输赢 → 奖励或轻任务开启赛后对话 → 流星雨时邀请一人，能接受、朋友同行或拒绝，玩家也可独自上楼 → 结算显示本晚关键行动与角色基于亲见事件的评价。

工程可先用“一名角色＋一款含酒精饮品＋一款无酒精饮品”打通状态链，再扩到四人九款；**交付给创作侧试玩的首夜样板**应覆盖四名角色参与五人比赛、至少两类邀请结果和四类结算出口。对白可以先用受控版本；Cash、饮用、投球和邀请答复不能只靠台词假装发生。

## 需要技术同学回传的三件事

1. 正在开发的 UE5 主工程绝对路径、目前可玩的关卡和 Agent／模型服务端的真实位置。
2. 哪些现成能力可以复用，哪些需要新做；特别是物理投球、饮品状态保存、事件可见性与角色记忆。
3. 第一条可玩链路的实际录屏或试玩包，以及未实现／暂用占位的功能清单。创作侧据此调节节奏、酒价、奖惩和角色反应。
